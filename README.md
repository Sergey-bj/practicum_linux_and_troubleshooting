Основы Linux: практическая работа

Задание:
На сервере работает процесс, который раз в секунду записывает текущее время в файл. 
Сам скрипт удалён с диска, но процесс продолжает работать. Нужно восстановить исходный код, не завершая процесс.

Шаги решения:
1. Создал скрипт `/opt/script.sh` с бесконечным циклом:
   echo 'while true; do date >> /opt/my.log; sleep 1; done' | sudo tee /opt/script.sh

2. Запустил отдельный процесс:
   sudo bash /opt/script.sh

3. Открыл второй терминал

4. Нашел процесс командой ps aux | grep script.sh
   root        1134  0.0  0.1  17144  7012 pts/0    S+   19:58   0:00 sudo bash /opt/script.sh
   root        1135  0.0  0.0  17144  2548 pts/1    Ss   19:58   0:00 sudo bash /opt/script.sh
   root        1136  0.0  0.0   7744  3476 pts/1    S+   19:58   0:00 bash /opt/script.sh
   Нужный  процесс PID 1136

5. Проверил структуру процесса ps -ef --forest | grep -A2 script
   root  1134  1026  sudo bash /opt/script.sh
   root  1135  1134   \_ sudo bash /opt/script.sh
   root  1136  1135       \_ bash /opt/script.sh
   root  2173  1136           \_ sleep 1
   Дочерний `sleep 1` — это работающий цикл: на каждой итерации bash порождает новый процесс `sleep`, 
   который завершается через секунду

6. Удалил скрипт sudo rm /opt/script.sh

7. Проверил, что процесс продолжает работу:
   cat /opt/script.sh - файла нет на диске
   ps aux | grep script.sh - процесс жив
   root  1136  0.0  0.0  7744  3476 pts/1  S+  19:58  0:00 bash /opt/script.sh
   tail -f /opt/my.log - лог пополняется 
   Wed Oct  7 20:12:46 UTC 2026
   Wed Oct  7 20:12:47 UTC 2026 
   Wed Oct  7 20:12:48 UTC 2026
   ... 

8. Почему процесс продолжает работать с удаленным файлом?
   Команда `rm` не стирает данные с диска. Она вызывает системный вызов `unlink()`, который удаляет имя файла из каталога,
   то есть запись «имя → номер inode». Сами данные и метаданные файла хранятся в inode. 
   У inode есть два счётчика:
       - счётчик жёстких ссылок - сколько имён указывает на этот inode;
       - счётчик открытых дескрипторов - сколько процессов держат файл открытым.
   Файл физически освобождается только тогда, когда оба счётчика равны нулю.
   Bash держит файл скрипта открытым всё время выполнения, он читает его по мере необходимости, 
   а не загружает целиком в память. Поэтому inode остаётся живым, а данные доступны через дескриптор процесса.

9. Механизм доступа к удаленному файлу:
   Механизм - виртуальная файловая система `/proc` (procfs), а именно каталог `/proc/<PID>/fd/`, 
   в котором ядро отображает все открытые процессом файловые дескрипторы в виде символических ссылок.
   sudo ls -l /proc/1136/fd/
   lrwx------ 1 root root 64 Oct  7 20:14 0 -> /dev/pts/1
   lrwx------ 1 root root 64 Oct  7 20:14 1 -> /dev/pts/1
   lrwx------ 1 root root 64 Oct  7 20:14 2 -> /dev/pts/1
   lr-x------ 1 root root 64 Oct  7 20:14 255 -> '/opt/script.sh (deleted)'
   Пометка `(deleted)` означает, что имени в файловой системе больше нет, но сам файл открыт и доступен. 
   Дескриптор 255 - служебный номер, который bash использует для чтения исполняемого скрипта:
   он берёт заведомо большой номер, чтобы не конфликтовать с дескрипторами самого скрипта.

10. Восстановил исходный код:
   sudo cat /proc/1136/fd/255 - чтение содержимого через дескриптор
   while true; do date >> /opt/my.log; sleep 1; done
   sudo cat /proc/1136/fd/255 | sudo tee /opt/script.sh - записал обратно на диск
   cat /opt/script.sh - проверил результат
   while true; do date >> /opt/my.log; sleep 1; done
